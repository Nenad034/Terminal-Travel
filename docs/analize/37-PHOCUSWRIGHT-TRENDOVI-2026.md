Priprema B2B API i baze podataka za eru autonomnih agenata (2027–2028) zahteva prelazak sa klasičnog web interfejsa na **determinističke mašinske transakcije**. Kada je klijent sa druge strane API-ja autonomni AI agent, a ne čovek u pretraživaču, arhitektura mora rešiti pet ključnih inženjerskih stubova.

---

### 1. Rešavanje „Look-to-Book” krize i arhitektura baze

Autonomni agenti neprekidno skeniraju rute i kombinacije, generišući stotine pretraga po jednom korisničkom zadatku. Povećan odnos pretraga i rezervacija (*Look-to-Book ratio*) ruši standardne relacione baze ako se upiti ne izoluju.

* **CQRS separacija (Command Query Responsibility Segregation):**
* **Read Layer:** Distribuirana in-memory skladišta (Redis / Dragonfly) i pretraživački indeksi (Meilisearch / Elasticsearch) za statičke podatke (opisi, fotografije, fiksne cene, pravila soba).
* **Write Layer:** PostgreSQL sa strogim ACID transakcijama, izolovan isključivo za procese zaključavanja raspoloživosti i kreiranja rezervacija.


* **Segmentirano keširanje (Stale-While-Revalidate):**
* Statički sadržaj (lokacije, sadržaji hotela) ima dug TTL (24–72h).
* Dinamičke cene se keširaju na Edge nivou (Cloudflare Workers / Supabase Edge Functions) sa TTL-om od 15–60 sekundi uz automatsku revalidaciju pri `pre-book` proveri.



---

### 2. Standardizacija za LLM agente (MCP i kompaktni tokeni)

Modeli poput Gemini-ja, Claude-a ili GPT-a gube kontekst i troše nepotrebne resurse ako im B2B API vraća megabajte ugnježdenog JSON-a.

* **Model Context Protocol (MCP) integracija:**
* Implementirajte namenski **MCP Server** sloj nad vašim B2B API-jem. Time omogućavate LLM agentima da standardizovano prepoznaju vaše alate bez pisanja namenskih *wrapper* skripti za svakog klijenta.


* **Token-Efficient Payload:**
* Smanjite verbose JSON odgovore. Zamenite opširne tekstualne opise standardizovanim šifarnicima (IATA, ISO kodovi soba, IATA NDC/ONE Order strukture).
* Koristite strogo tipizirane OpenAPI 3.1 šeme sa jasnim, sažetim `description` anotacijama koje vode LLM tokom *Tool Calling-a*.


* **Semantički indeks (pgvector / HNSW):**
* Indeksirajte nestrukturisani inventar (npr. specifične pogodnosti, mikrolokacije, recenzije). Agent koji dobije upit „hotel pogodan za rad na daljinu blizu metroa” prvo radi vektorski pre-filter, a potom proverava cene samo za top 3 kandidata.



---

### 3. Mašinski proces rezervacije (*Two-Phase Commitment*)

Agenti ne mogu popunjavati web forme niti reagovati na nepredviđene greške u sesiji. Potrebna je deterministička dvofazna transakcija:

```
[Agent Intent] ──> 1. Pre-Book / Soft Hold ──> 2. Pass Tokenized ID & Wallet ──> 3. Confirm & Issue
                         (Privremeno zaključavanje)     (Jednokratna autorizacija)          (IATA / PNR potvrda)

```

1. **Offer & Soft-Lock Endpoint (`POST /offers/hold`):**
* Kreira privremeni `offer_id` sa garantovanom cenom i raspoloživošću koji važi 5 do 15 minuta.


2. **Idempotencija transakcija:**
* Obavezno uvođenje `Idempotency-Key` hedera na svim rutama plaćanja i kreiranja rezervacija kako mrežni retries agenta ne bi napravili duple rezervacije.


3. **Strogo tipizirane greške (Machine-actionable Errors):**
* Umesto generičkog `500 Server Error` ili `400 Bad Request`, API mora vraćati strukturisane greške koje agent može sam da razreši (npr. `{"error": "ROOM_UNAVAILABLE", "suggested_alternative_id": "std_twin_02"}`).



---

### 4. Bezbednost i razdvajanje plaćanja od rezonovanja

Autonomni agent nikada ne sme imati direktan pristup platnim karticama ili neograničenim API ključevima.

* **Scoped OAuth 2.0 & Granularne dozvole:**
* Kredencijali agenta moraju imati precizno definisane limite (npr. `scope: [search, hold]`, dok `scope: [book]` zahteva limit do npr. 500 € ili eksplicitnu potvrdu vlasnika).


* **Integracija sa Digitalnim novčanicima (EU Digital Identity Wallet / Agent-ready SDK):**
* Prihvatanje kriptografski potpisanih podataka o putniku (pasoš, lojaliti broj) i privremenih tokena za naplatu (Virtual Credit Cards / delegated payment tokens) direktno u *checkout* pozivu.

### 2. Python kontroler (MCP Server implementacija)

Server koristi `mcp` Python SDK (preko standardnog I/O ili SSE transporta) i komunicira sa B2B API / Redis / PostgreSQL slojem.

```python
import os
import uuid
import asyncio
from datetime import datetime, timezone, timedelta
from typing import Any, Dict
from mcp.server.fastmcp import FastMCP
from pydantic import BaseModel, Field

# Inicijalizacija FastMCP servera
mcp = FastMCP("TravelB2BAgentGateway")

# Pydantic modeli za strogu validaciju ulaza
class SearchInventoryInput(BaseModel):
    service_type: str = Field(..., description="HOTEL ili FLIGHT")
    destination: str = Field(..., min_length=3, max_length=3, description="IATA 3-letter code")
    check_in_date: str = Field(..., description="YYYY-MM-DD")
    check_out_date: str = Field(..., description="YYYY-MM-DD")
    origin: str | None = Field(None, min_length=3, max_length=3)
    passengers_count: int = Field(1, ge=1, le=9)

class OfferHoldInput(BaseModel):
    offer_id: str
    passenger_id_token: str

class ConfirmBookingInput(BaseModel):
    hold_id: str
    payment_token: str
    idempotency_key: str

# 1. Endpoint / Alat za pretragu
@mcp.tool()
async def search_travel_inventory(params: SearchInventoryInput) -> Dict[str, Any]:
    """Pretraga raspoloživosti u realnom vremenu optimizovana za brz odziv i minimalan broj tokena."""
    
    # Simulacija poziva ka distribuiranom kešu / agregatoru
    # U produkciji: poziv ka Redis / Meilisearch / B2B provajderu
    mock_offers = [
        {
            "offer_id": f"off_{params.destination.lower()}_001",
            "title": "Grand Central Premium Hotel",
            "room_type": "Standard King",
            "currency": "EUR",
            "total_price": 320.00,
            "refundable": True,
            "cancellation_deadline": f"{params.check_in_date}T18:00:00Z"
        },
        {
            "offer_id": f"off_{params.destination.lower()}_002",
            "title": "City Center Smart Suites",
            "room_type": "Executive Double",
            "currency": "EUR",
            "total_price": 285.50,
            "refundable": False,
            "cancellation_deadline": None
        }
    ]
    
    return {
        "status": "SUCCESS",
        "destination": params.destination,
        "count": len(mock_offers),
        "offers": mock_offers
    }

# 2. Endpoint / Alat za privremeno zaključavanje cene i sobe (Soft-Hold)
@mcp.tool()
async def create_offer_hold(params: OfferHoldInput) -> Dict[str, Any]:
    """Zaključava cenu i raspoloživost na 15 minuta pre izvršenja naplate."""
    
    # Generisanje TTL-a za privremeni lock
    hold_expires_at = datetime.now(timezone.utc) + timedelta(minutes=15)
    hold_id = f"hld_{uuid.uuid4().hex[:10]}"
    
    # Ovde se u bazi / Redisu postavlja lock: key=hold_id, ttl=900s
    return {
        "status": "HELD",
        "hold_id": hold_id,
        "locked_offer_id": params.offer_id,
        "guaranteed_price": 320.00,
        "currency": "EUR",
        "expires_at_utc": hold_expires_at.isoformat(),
        "action_required": "Confirm booking before expiry with valid payment token."
    }

# 3. Endpoint / Alat za potvrdu rezervacije i plaćanje
@mcp.tool()
async def confirm_booking_transaction(params: ConfirmBookingInput) -> Dict[str, Any]:
    """Izvršava transakciju rezervacije i izdaje PNR/vaučer uz zaštitu idempotencije."""
    
    # Validacija Idempotency ključa u PostgreSQL bazi
    # Ako je ključ već obrađen, vraća se keširani odgovor kako se ne bi ponovila naplata
    
    pnr_code = f"TTA{uuid.uuid4().hex[:6].upper()}"
    
    return {
        "status": "CONFIRMED",
        "pnr": pnr_code,
        "hold_id": params.hold_id,
        "idempotency_key": params.idempotency_key,
        "issued_at_utc": datetime.now(timezone.utc).isoformat(),
        "voucher_url": f"https://api.domain.com/v1/vouchers/{pnr_code}.pdf"
    }

if __name__ == "__main__":
    # Pokretanje servera
    mcp.run()

```

### 3. Ključne prednosti ove arhitekture

* **Idempotentnost (`idempotency_key`):** Mrežni prekidi ili ponovljeni agentski pozivi ne mogu izazvati višestruku naplatu ili dvostruke rezervacije u GDS/PMS sistemu.
* **Token-efikasnost:** Vraćaju se samo suštinski parametri (ID, cena, valuta, rokovi otkazivanja), što sprečava zagušenje kontekstnog prozora LLM-a.
* **Frictionless autorizacija:** Razdvajanje pretrage od soft-hold faze omogućava agentu da sačuva resurs dok u pozadini obavlja brzu autorizaciju sa digitalnim novčanikom putnika.
